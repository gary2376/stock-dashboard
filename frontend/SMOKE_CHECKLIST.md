- [ ] 確認後會儲存同意狀態；之後載入時不再顯示彈出視窗。若 localStorage 遭封鎖，頁面仍可正常運作，且每次載入都會顯示彈出視窗。
- [ ] 免責聲明頁尾與 TradingView 出處連結會顯示於 index.html、dashboard.html、detail.html、strategy.html 和 overview.html。
- [ ] 在行動裝置寬度下，彈出視窗與頁尾不會造成水平捲動。
- [ ] 當 `/api/info` 回傳 `{demo:true}` 時，每個頁面都會顯示固定且無法永久關閉的示範模式橫幅，其中包含合成資料警告與 GitHub README 連結；會設定 `<html data-demo="1">`，橫幅不會使行動版版面位移，導覽仍可正常開始及重播。
- [ ] `/api/info` 遺失、回傳 404、無效或無法連線時，會視為非示範模式且不會造成任何頁面故障；每次頁面載入只會擷取端點一次，且 `window.sdDemo.isDemo()` / `onReady()` 會正常解析。
- [ ] 在示範模式中，首頁新增／更新控制項、個股頁策略檢查、總覽頁批次檢查及聊天傳送功能都會停用，並提供 title 與 `aria-describedby` 說明。聊天泡泡仍可開啟，且第一則助理訊息會說明示範模式；忙碌／輪詢／呈現狀態切換絕不會重新啟用這些控制項。
- [ ] Pin 編譯在示範模式中仍維持啟用：僅使用範本的規則仍可編譯，而經過 LLM 路徑時若收到 403，會逐字顯示後端 `detail` 文字並恢復該列控制項。
- [ ] 在不支援 `showModal()` 的瀏覽器中，同意流程的備援介面仍會開啟、將焦點限制在確認按鈕、阻止以 Escape 關閉、正常完成確認並恢復焦點。
- [ ] 第一次造訪 `index.html`、`dashboard.html`、`detail.html`、`strategy.html` 和 `overview.html` 的各個頁面時，導覽會等到同意對話框確認後才啟動一次；重新載入該頁面不會再次自動啟動。
- [ ] 若 localStorage 遭封鎖，導覽仍可運作，且不會在同一份文件中反覆自動啟動；固定於左下角的 `？ 導覽` 按鈕可隨時重播導覽，且不會遮住右下角的 AI 泡泡或免責聲明文字。
- [ ] 每個導覽步驟都會將目標捲動至可見範圍、調暗頁面其餘部分、勾勒目標外框、顯示繁體中文的 WHAT/WHY 文案與正確的 `n / total`，並支援上一步、下一步／完成、略過導覽。
- [ ] 導覽鍵盤操作：開啟時焦點會移至下一步，Tab 和 Shift+Tab 會將焦點保持在對話框內，Escape 會略過／關閉導覽，且焦點會回到重播按鈕（或先前聚焦的元素）。
- [ ] 移除或隱藏選用目標（沒有觀察清單卡片、持股、雷達評分或部位備註）；對應步驟會靜默略過，其餘導覽仍可完成。
- [ ] 在 390px 寬度下，每個導覽彈出框都位於可視區域內且不會出現水平捲動；啟用減少動態效果時，聚光燈移動與目標捲動不會播放動畫。
- [ ] 首頁導覽包含策略批次總覽導覽連結。持股存在時，儀表板導覽會標示總計、持股圓餅圖和損益長條圖。個股頁導覽涵蓋圖表／繪圖、區間、五軸證據警告／原因、持股批次、分析、策略檢查的驗證意義，以及選用的部位備註。
- [ ] 個股頁圖表預設開啟 MA20／MA50／MA200／成交量，並關閉 MA10；每個切換按鈕都有可見的色票、可使用鍵盤操作、會宣告其按下狀態、在 390px 寬度下運作時不會造成頁面層級的水平捲動，且重新載入後會恢復其狀態（localStorage 遭封鎖時仍可運作）。
- [ ] 即使選取較短區間，MA 線仍使用完整的 3 年 K 線資料集；略過尚未累積足夠週期的日期、不顯示最後數值標籤，且切換區間不會重新計算或移除 MA 線。
- [ ] 成交量長條顯示於價格圖表底部，漲跌使用不同的半透明顏色；若快取回應缺少 `volume`，會略過對應 K 線，而完全不含成交量的舊快取仍可正常呈現價格圖表且不會出錯。
- [ ] 將游標停留在圖表上時，會顯示日期以及已啟用 MA 與成交量的數值；移開指標後會清除懸停圖例。
- [ ] 切換指標後，所有區間按鈕仍可平移／縮放，趨勢線繪製／清除仍可運作，買入日期標記與平均價格線仍可正常呈現及切換。個股頁導覽包含指標切換步驟，同時保留 `#priceChartPanel` 與 `#rangeBtns` 步驟。
- [ ] 讓同意對話框保持開啟超過 10 秒，或在開啟時離開頁面；導覽的同意等待觀察器會逾時／中斷連線，之後不會由過期的觀察器啟動。
- [ ] 策略導覽會說明備註的重要性、上傳、貼上、限制，以及備註會保留在本機 `data/strategy`，且只會在執行檢查時傳送給已登入的 AI CLI。
- [ ] `strategy.html` 會顯示目前的位元組／檔案使用量與限制，且沒有備註時會呈現清楚的空白狀態。
- [ ] 上傳功能接受 UTF-8 `.md`/`.txt`；若檔案超過伺服器回報的單檔／總量限制，會在傳送前拒絕；遇到非 UTF-8 位元組時會拒絕且不發出 PUT，並顯示後端 400/413 詳細資訊。
- [ ] 貼上並儲存前，會依伺服器回報的單檔及總量限制預先檢查 UTF-8 位元組大小；檢視、確認後刪除及重新整理功能都可運作；檔名和備註內容若包含 `<script>`、引號及 `&`，只會呈現為文字。
- [ ] 以延遲回應讓兩次策略檔案清單重新整理重疊；只有最新的回應會更新使用量與清單。刪除備註後，鍵盤焦點會移到已儲存備註的標題。
- [ ] 個股頁策略面板會在載入時呈現已儲存的結果，包含時間戳記、引擎、持股批次狀態、收合的警告、全部四種徽章狀態、逐字引文／脈絡、證據，以及僅限非空白的情境建議。
- [ ] 個股頁策略結果一律顯示範圍說明與 `現在` 區段；缺少 `scope` 的列會呈現於該區段並附上 `現在` 徽章。買入列會呈現在獨立的 `買入當時` 區段，分組於 `N. YYYY-MM-DD 買入 @價格` 下，分組資訊來自 `entry_lots_checked`/`lot_date`，並附上 `買入當時 第N筆` 徽章；沒有買入列時不會顯示買入區段。
- [ ] 有持股時，個股頁策略中繼資料會顯示 `（損益為截至今日）`；HOLD 證據與過期結果通知的行為維持不變。
- [ ] 策略面板跳脫處理：含有 HTML 的規則／來源／引文／脈絡／證據／建議／警告／API 錯誤會呈現為文字，絕不執行標記。
- [ ] 執行檢查時約每 3 秒輪詢一次，並在完成／錯誤／離開頁面時停止且恢復按鈕；固定的免責聲明會保持在每個結果上方。若結果的 ticker 與頁面 ticker 不同，會視為沒有結果。
- [ ] 延遲初始狀態 GET，直到較新的 POST／輪詢 GET 完成後才回應；延遲的回應不得覆寫較新的狀態。
- [ ] POST 409 會顯示另一個全域執行中檢查的伺服器詳細資訊、維持按鈕可用，且不會載入這個 ticker 的舊結果或將其標示為完成；400（包含無備註的詳細資訊）與 404 訊息會清楚顯示，且不會清除最後儲存的結果。
- [ ] 輪詢期間，暫時性 GET 失敗會顯示連線／重試訊息，並約在 3 秒、6 秒、12 秒後重試，且不會延長原本的 10 分鐘期限。
- [ ] 檢查執行期間，透過 BFCache 離開頁面再返回；頁面重新啟用後會恢復／重新擷取狀態，而不會維持停止狀態。
- [ ] 策略頁與個股頁面板在行動裝置寬度下不會出現水平捲動；所有控制項皆可使用鍵盤操作，且焦點清楚可見。
- [ ] 策略 Pin 會依儲存順序載入並顯示目前／最大數量；新增時會使用所選的現在／買入當時／兩者 scope，以及伺服器 `max_text` maxlength。範例按鈕會同時填入文字與 scope（`買入時…` → entry，其餘 → now），事實目錄展開後會依 key prefix 將事實分組。
- [ ] Pin 的建立／更新／刪除／重新排序／編譯／確認異動共用單一序列佇列。受影響的列會立即停用，每個請求都使用最新採用的 revision，且每次成功回應都會立即更新本機 revision／資料，而不需後續 GET。
- [ ] 修改 Pin 文字後立即點擊確認：文字更新會先完成，舊的解讀絕不會被確認，新文字仍保持可見，且只有目前草稿可供確認。Scope／enabled 編輯、刪除及重新排序同樣會保存。
- [ ] 文字／scope／enabled 更新及上移／下移重新排序造成清單重新呈現後，若相同控制項仍存在，鍵盤焦點會回到相同的 Pin ID 及控制項／動作。
- [ ] revision 衝突的 409 會重新載入清單並顯示 `清單已在別處更新，已重新載入`；編譯忙碌的 409 若詳細資訊提及 compile／編譯／另一個，則會顯示該後端詳細資訊。之後鍵盤控制仍可使用。
- [ ] Pin 編譯會顯示 `AI 編譯中，最多約 3 分鐘…`，並在請求結束前停用該列的控制項。約 200 秒後或觸發 `pagehide` 時會中止，接著顯示 `編譯逾時或已中止，請稍後重試` 並重新啟用控制項；429 會顯示後端詳細資訊。
- [ ] 草稿 Pin 會醒目顯示每個 scope 的人類可讀重述、以程式碼呈現的運算式及事實清單，並且只有一個 `確認這個解讀` 按鈕。編輯已確認的文字後，會依後端狀態變成已過期／待重新編譯。不支援的原因會使用指定的白話中文對應，並以 `其他原因` 作為備援。
- [ ] 個股頁會在策略面板正上方載入 `/api/pins/eval/{ticker}`。每個結果都有文字徽章（通過／未通過／未知）、規則文字與證據；買入結果會顯示 `N. YYYY-MM-DD 買入：badge evidence`，空白結果則會連結至 Pin 管理。
- [ ] `both` Pin 若缺少買入側（`entry_reason` 或沒有買入列），以及 `entry` Pin 沒有買入列時，整體狀態絕不會顯示通過。它們會顯示未知／部分未知，且即使已有其他狀態／原因，也一定會顯示 `entry_reason`。
- [ ] 新增、刪除或清空持股時，會透過將 AI 策略結果標記為過期的相同持股變更路徑，自動重新整理個股頁 Pin 評估；固定檢查標籤會說明這是直接計算且未使用 AI。
- [ ] 不含 `pins` 的總覽 payload 會與先前完全相同地呈現。當 `overview.pins` 存在時，Pin 會依穩定的回應順序呈現為矩陣的最前面幾列，以 Pin 文字作為列標題、顯示文字狀態徽章，並與後續的備註規則列清楚區隔。

- [ ] 首頁在策略筆記旁提供前往 `overview.html` 的連結；總覽頁會連回首頁及策略筆記管理，且其導覽涵蓋 ticker 選擇、執行按鈕、矩陣與用量區塊。

- [ ] 延遲初始總覽批次 GET，直到較新的 POST／輪詢 GET 完成後才回應；過期的回應絕不會覆寫較新的狀態。
